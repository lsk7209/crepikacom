핵심 개요

구글 검색 결과에서 별점, 가격, FAQ, 레시피 단계처럼 일반 블루 링크보다 눈에 띄는 결과를 본 적 있으신가요? 이것이 스키마 마크업(구조화 데이터)을 통해 만들어지는 리치 스니펫(Rich Snippet)입니다. 리치 스니펫은 클릭률을 20~30% 높인다는 연구 결과가 있습니다. 스키마를 직접 추가하는 방법을 알면 플러그인 없이도 구글에 더 많은 정보를 전달할 수 있습니다. 이 글에서 소개하는 방법들은 실제 운영 경험을 바탕으로 엄선한 실전 전략입니다. 실제 운영 현장에서 검증된 접근법으로, 지금 당장 적용할 수 있는 내용을 중심으로 구성했습니다. 실전에 바로 쓸 수 있는 글자수 세기과 해시태그 믹서을 활용하면 이 가이드의 내용을 더욱 빠르게 적용할 수 있습니다.

스키마 마크업 기초: JSON-LD 형식

스키마 마크업을 추가하는 방법 중 JSONLD(JavaScript Object Notation for Linked Data)가 구글에서 가장 권장하는 방식입니다. HTML 코드와 분리되어 관리하기 쉽고, script 태그 안에 넣으면 됩니다. 기본 구조는 다음과 같습니다. script 태그에 type="application/ld+json"을 지정하고, 안에 JSON 형식으로 @context, @type, 그리고 해당 타입의 속성들을 작성합니다. Article 스키마라면 headline, author, datePublished, dateModified, image, publisher 등이 필수 속성입니다. HTML head 또는 body 어디에나 삽입할 수 있지만, head 안에 넣는 것이 일반적입니다.

가장 효과적인 스키마 유형 3가지

FAQ 스키마: 블로그 포스트 하단에 FAQ 섹션이 있다면 FAQPage 스키마를 추가하면 구글 검색 결과에서 질문답변이 펼쳐지는 리치 스니펫이 나타납니다. @type: FAQPage, mainEntity 배열에 각 질문(@type: Question)과 답변(@type: Answer)을 작성합니다. Article 스키마: 일반 블로그 포스트에 적용합니다. headline, author, datePublished, image, publisher를 포함하면 구글이 포스트를 더 정확하게 분류합니다. HowTo 스키마: 단계별 방법을 설명하는 글에 적용합니다. 각 단계를 HowToStep으로 나열하면 검색 결과에서 단계별 목록이 미리 보이는 리치 스니펫이 표시됩니다.

스키마 검증과 구글 적용 확인

스키마를 추가한 후 오류가 없는지 반드시 검증해야 합니다. 검증 도구: 구글의 리치 결과 테스트(search.google.com/test/richresults)에 URL 또는 코드를 붙여넣으면 스키마가 올바르게 작성됐는지 즉시 확인할 수 있습니다. 오류나 경고가 있으면 해당 속성을 수정하세요. 적용 확인: 스키마를 추가하고 색인이 되면 구글 서치 콘솔의 "리치 결과" 섹션에서 어떤 스키마가 유효하게 감지됐는지 확인할 수 있습니다. 실제 검색 결과에 리치 스니펫이 표시되기까지는 1~4주가 걸릴 수 있습니다. 모든 페이지에 리치 결과가 표시되는 것은 아닙니다. 구글이 스키마가 정확하고 페이지 내용과 일치한다고 판단할 때만 표시합니다.

스키마 추가 시 주의사항

실제 내용과 스키마 데이터 일치: 스키마에 5점 별점을 넣었는데 페이지에 실제 리뷰가 없다면 구글 가이드라인 위반입니다. 스키마에 있는 모든 정보는 페이지 콘텐츠에 실제로 표시되어야 합니다. 과도한 스키마 사용 금지: 관련 없는 스키마를 많이 추가한다고 리치 결과가 더 많이 표시되지 않습니다. 페이지 콘텐츠에 맞는 1~2개 스키마만 정확하게 작성하세요. 정기적 업데이트: 날짜, 가격, 운영 시간처럼 변경되는 정보를 스키마에 포함했다면 실제 변경 시 스키마도 함께 업데이트해야 합니다. 불일치하면 구글이 리치 결과 표시를 중단할 수 있습니다.

마무리

스키마 마크업은 검색 결과에서 경쟁자와 시각적으로 차별화되는 가장 효과적인 SEO 기법입니다. FAQ 스키마부터 시작해서 구글 리치 결과 테스트로 검증하고, 서치 콘솔에서 적용 여부를 확인하세요.

자주 묻는 질문

스키마 마크업이 랭킹에 직접 영향을 주나요?

구글은 스키마 마크업 자체가 랭킹을 올려준다고 공식적으로 밝히지 않습니다. 하지만 리치 스니펫으로 클릭률이 오르면 사용자 행동 신호가 개선되어 간접적으로 랭킹에 유리합니다. 또한 구글이 페이지 내용을 더 정확하게 이해하는 데 도움을 줍니다.

WordPress 사용자도 JSON-LD를 수동으로 추가해야 하나요?

WordPress에서는 Yoast SEO나 RankMath 같은 플러그인이 스키마를 자동으로 추가합니다. 추가 스키마(FAQ, HowTo 등)는 플러그인의 스키마 블록 기능을 쓰거나, 직접 JSONLD를 HTML 편집기로 추가할 수 있습니다. 플러그인이 없는 Vercel 사이트나 커스텀 블로그는 직접 추가해야 합니다.

스키마를 잘못 작성하면 패널티가 있나요?

실제 콘텐츠와 다른 허위 정보를 스키마에 담으면 구글이 리치 결과 표시를 차단하고 심각한 경우 수동 조치(Manual Action)를 받을 수 있습니다. 단순 문법 오류나 빠진 속성은 리치 결과가 표시되지 않을 뿐 패널티는 없습니다.

FAQ 스키마에는 몇 개의 질문을 넣는 것이 좋나요?

3~8개가 적당합니다. 너무 적으면 리치 결과 가치가 낮고, 너무 많으면 검색 결과에서 일부만 표시됩니다. 검색자가 가장 많이 가질 법한 질문 5개를 선별해 정확하고 간결한 답변을 작성하세요. FAQ 내용은 반드시 페이지 본문에도 실제로 표시되어야 합니다.

리뷰 스키마(별점)는 어떤 페이지에 추가할 수 있나요?

구글은 자사 제품/서비스에 대한 자체 리뷰 스키마는 허용하지 않습니다. 제3자 리뷰어가 작성한 리뷰에만 리뷰 스키마를 적용할 수 있습니다. 제품 페이지가 아닌 북 리뷰, 앱 리뷰, 로컬 비즈니스 리뷰 같은 명확한 리뷰 콘텐츠에만 적용하세요.

사이트 검토 정보

크레피카는 크리에이터와 마케터를 위한 무료 유틸리티 사이트입니다. 실무 도구, 편집 가이드, 문의 정보, 개인정보처리방침, 이용약관, RSS, robots.txt, ads.txt, 사이트맵을 제공해 사용자와 검색엔진이 자바스크립트 렌더링에만 의존하지 않고 사이트 구조를 이해할 수 있게 합니다.

광고는 Google AdSense 자동 광고로 노출될 수 있습니다. 이 정적 크롤러 페이지에는 수동 광고 슬롯을 삽입하지 않으며, 광고는 도구 결과나 편집 추천 내용에 영향을 주지 않습니다.
