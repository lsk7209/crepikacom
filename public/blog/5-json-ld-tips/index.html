리치 스니펫 빠르게 달기 위한 5가지 JSON-LD 팁: 복사해서 바로 적용하기

JSON-LD 구조화 데이터를 처음 적용하는 분들을 위해 복사해서 바로 쓸 수 있는 5가지 스키마 템플릿과 실수 없이 적용하는 팁을 정리했습니다.

Overview

구글 검색 결과에서 별점, FAQ 아코디언, 레시피 이미지, 브레드크럼 경로처럼 추가 정보가 표시되는 것을 리치 스니펫(Rich Snippet)이라고 합니다. 리치 스니펫이 붙으면 클릭률(CTR)이 평균 20~30% 상승한다는 연구 결과가 있습니다. 이 리치 스니펫을 만드는 기술이 바로 구조화 데이터(Structured Data)이고, 가장 권장되는 구현 방식이 JSONLD입니다. 많은 분들이 JSONLD를 '개발자만 건드리는 것'으로 생각하지만, 실제로는 코드 한 블록을 HTML에 붙여넣는 수준으로 구현할 수 있습니다. WordPress라면 플러그인 하나로도 됩니다. 이 글에서는 가장 많이 쓰이는 5가지 JSONLD 스키마 유형과 바로 복사해서 적용할 수 있는 템플릿 코드를 제공합니다. 각 스키마의 적용 방법, 테스트 방법, 자주 발생하는 오류도 함께 설명합니다.

팁 1: FAQ 스키마로 검색 결과에 질문·답변 아코디언 달기

FAQ 스키마는 블로그 글 하단의 자주 묻는 질문 섹션을 구글 검색 결과에 바로 표시합니다. 검색 결과에서 질문 제목을 클릭하면 펼쳐지는 아코디언 형태로 노출되어 CTR을 크게 높입니다. 적용 조건: 페이지에 명확한 질문과 답변 쌍이 2개 이상 있어야 합니다. 템플릿: <script type='application/ld+json'{ "@context": "https://schema.org", "@type": "FAQPage", "mainEntity": [{ "@type": "Question", "name": "질문 1", "acceptedAnswer": { "@type": "Answer", "text": "답변 1" }}, { "@type": "Question", "name": "질문 2", "acceptedAnswer": { "@type": "Answer", "text": "답변 2" }}]}</script. 적용 방법: 이 코드를 HTML 파일의 </body 태그 바로 위에 붙여넣거나, WordPress라면 Rank Math 또는 Yoast SEO의 Schema 탭에서 FAQ 스키마를 직접 추가합니다. 주의: 답변 텍스트가 너무 짧거나(100자 미만), 질문이 실제로 페이지 내에 없으면 리치 스니펫이 표시되지 않을 수 있습니다.

팁 2: Article 스키마로 뉴스·블로그 콘텐츠의 신뢰도 신호 보내기

Article 스키마는 블로그 게시글이나 뉴스 기사가 구글에게 '이것은 전문가가 작성한 글입니다'라는 신호를 명확하게 전달합니다. EEAT 신호 강화에 직접 기여합니다. 템플릿: <script type='application/ld+json'{ "@context": "https://schema.org", "@type": "Article", "headline": "글 제목", "author": { "@type": "Person", "name": "저자 이름", "url": "https://example.com/author/name" }, "datePublished": "20260508", "dateModified": "20260508", "publisher": { "@type": "Organization", "name": "사이트명", "logo": { "@type": "ImageObject", "url": "https://example.com/logo.png" }}, "image": "https://example.com/articleimage.jpg" }</script. 핵심 필드 설명: datePublished와 dateModified는 ISO 8601 형식(YYYYMMDD)으로 입력합니다. author의 url을 저자 소개 페이지로 연결하면 EEAT 신호가 강화됩니다. image는 1200px 이상의 고품질 이미지여야 Discover 노출에도 유리합니다. WordPress라면 Rank Math가 자동으로 Article 스키마를 생성하고 GSC와 동기화합니다.

팁 3: BreadcrumbList 스키마로 URL 대신 경로 표시하기

브레드크럼(Breadcrumb) 스키마는 구글 검색 결과에서 URL 대신 '홈 카테고리 글 제목' 형태의 경로를 표시합니다. 사이트 구조를 명확하게 보여줘서 클릭률을 높이고, 구글이 사이트 계층 구조를 이해하는 데 도움을 줍니다. 템플릿: <script type='application/ld+json'{ "@context": "https://schema.org", "@type": "BreadcrumbList", "itemListElement": [{ "@type": "ListItem", "position": 1, "name": "홈", "item": "https://example.com" }, { "@type": "ListItem", "position": 2, "name": "카테고리", "item": "https://example.com/category" }, { "@type": "ListItem", "position": 3, "name": "페이지 제목", "item": "https://example.com/category/page" }]}</script. 적용 팁: 브레드크럼 스키마는 페이지의 실제 UI에 브레드크럼 네비게이션이 있을 때 효과가 더 좋습니다. 스키마만 있고 실제 UI에 브레드크럼이 없으면 리치 스니펫이 표시되지 않을 수 있습니다. Yoast SEO와 Rank Math는 사이트 카테고리 구조를 자동으로 인식해 브레드크럼 스키마를 생성합니다.

팁 4: Product 스키마로 이커머스 상품에 별점·가격 노출하기

Product 스키마는 상품 페이지에 별점, 리뷰 수, 가격, 재고 상태를 구글 검색 결과에 직접 표시합니다. 이커머스에서 가장 전환율 향상 효과가 큰 리치 스니펫입니다. 필수 필드 포함 템플릿: <script type='application/ld+json'{ "@context": "https://schema.org", "@type": "Product", "name": "상품명", "image": "https://example.com/product.jpg", "description": "상품 설명", "sku": "SKU001", "brand": { "@type": "Brand", "name": "브랜드명" }, "offers": { "@type": "Offer", "price": "29000", "priceCurrency": "KRW", "availability": "https://schema.org/InStock", "url": "https://example.com/product" }, "aggregateRating": { "@type": "AggregateRating", "ratingValue": "4.7", "reviewCount": "128" }}</script. 중요 주의사항: 구글은 2024년부터 판매자 자신이 작성한 리뷰에 대한 Product 별점 리치 스니펫 표시 기준을 강화했습니다. 실제 사용자 리뷰 기반 데이터를 사용해야 합니다. Shopify와 WooCommerce는 플러그인(Schema Pro, Yoast WooCommerce SEO)을 통해 자동으로 Product 스키마를 생성합니다.

팁 5: Organization + WebSite 스키마로 사이트 기본 정보 등록하기

Organization과 WebSite 스키마는 사이트에 한 번만 설정하면 되는 기본 스키마입니다. 구글에게 '이 사이트의 운영자, 이름, 로고, 연락처'를 명확하게 알려줍니다. 구글 지식 패널(Knowledge Panel) 등록에도 도움이 됩니다. 조합 템플릿: <script type='application/ld+json'{ "@context": "https://schema.org", "@graph": [{ "@type": "WebSite", "@id": "https://example.com/website", "url": "https://example.com", "name": "사이트명", "potentialAction": { "@type": "SearchAction", "target": "https://example.com/?s={searchtermstring}", "queryinput": "required name=searchtermstring" }}, { "@type": "Organization", "@id": "https://example.com/organization", "name": "조직명", "url": "https://example.com", "logo": { "@type": "ImageObject", "url": "https://example.com/logo.png", "width": 512, "height": 512 }, "sameAs": ["https://www.instagram.com/example", "https://twitter.com/example"]}]}</script. sameAs 필드에 모든 공식 SNS 계정 URL을 포함시키면 구글이 브랜드 엔티티를 인식하는 데 도움이 됩니다. 이 스키마는 홈페이지 HTML에만 한 번 추가하면 됩니다. 적용 후 Google Rich Results Test에서 반드시 오류 여부를 확인하세요.

Conclusion

JSONLD 구조화 데이터는 한 번 적용해 두면 장기간 SEO 혜택을 받는 인프라 투자입니다. FAQ 스키마로 클릭률을 높이고, Article 스키마로 EEAT를 강화하며, Breadcrumb으로 사이트 구조를 명확히 하고, Product 스키마로 이커머스 전환율을 높이고, Organization 스키마로 브랜드 신뢰도를 구축하는 5가지를 우선 적용하세요. 적용 후에는 반드시 Google Rich Results Test와 Google Search Console의 리치 스니펫 보고서로 검증하는 것을 잊지 마세요.

FAQ

JSON-LD를 적용했는데 리치 스니펫이 표시되지 않는 이유는 무엇인가요?

리치 스니펫 표시 여부는 구글이 최종적으로 결정하며, 스키마가 올바르게 구현되어도 노출을 보장하지 않습니다. 일반적으로 적용 후 1~4주가 지나야 효과가 나타납니다. 오류 없이 적용됐는지 Rich Results Test에서 먼저 확인하고, GSC의 '리치 스니펫' 보고서에서 경고나 오류 메시지를 점검하세요.

WordPress에서 JSON-LD를 쉽게 적용하는 방법이 있나요?

Rank Math SEO와 Yoast SEO 플러그인이 가장 많이 사용됩니다. Rank Math는 글 편집 화면에서 Schema 탭으로 직접 스키마 유형을 선택하고 필드를 채울 수 있어 코드 없이 구현 가능합니다. Schema Pro 플러그인은 더 다양한 스키마 유형과 고급 설정을 지원합니다. 수동 적용이 필요하다면 functions.php나 헤더 삽입 플러그인(Insert Headers and Footers)을 활용하세요.

여러 스키마를 같은 페이지에 동시에 적용해도 되나요?

네, 가능합니다. 한 페이지에 Article + FAQPage + BreadcrumbList 스키마를 동시에 적용하는 것은 허용됩니다. @graph 배열을 사용하면 여러 스키마를 하나의 <script 태그에 묶을 수 있습니다. 단 @type을 잘못 설정하거나 필수 필드를 누락하면 특정 스키마만 유효하게 인식될 수 있으니 각각 Rich Results Test로 검증하세요.

구조화 데이터를 잘못 적용하면 구글에서 페널티를 받나요?

구조화 데이터 오남용(실제 콘텐츠와 일치하지 않는 스키마, 리뷰 조작 등)은 구글 수동 조치의 대상이 됩니다. 하지만 단순한 코드 오류나 불완전한 스키마는 페널티가 아니라 리치 스니펫 미표시로 이어질 뿐입니다. 항상 페이지 실제 내용과 스키마 내용이 일치하도록 유지하는 것이 중요합니다.

JSON-LD와 Microdata, RDFa 중 어떤 방식을 사용해야 하나요?

구글은 세 가지 방식 모두 지원하지만 JSONLD를 공식적으로 권장합니다. JSONLD는 HTML 구조와 분리되어 있어 유지보수가 쉽고, 실수가 적습니다. Microdata는 HTML 태그 안에 직접 속성을 추가하는 방식으로 기존 코드 수정이 필요해 복잡합니다. 신규 구현이라면 항상 JSONLD를 선택하세요.
