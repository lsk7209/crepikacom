핵심 개요

전자상거래 데이터를 정확히 수집하는 것은 마케팅 효율 개선의 출발점이다. 많은 이커머스 운영팀이 GA4 전환 추적을 제대로 구축하지 못한 채 불완전한 데이터로 의사결정을 내리고 있다. 정확하지 않은 전환 데이터가 가져오는 가장 큰 문제는 광고 채널별 기여도를 잘못 측정해 예산 배분을 왜곡한다는 것이다. 어떤 채널이 진짜 구매자를 데려오는지 모른 채 단순 트래픽 볼륨 기준으로 예산을 쓰는 것은 매달 수백만 원의 낭비를 만들어낸다. 서울에서 반려동물 용품을 전문으로 판매하는 이커머스 브랜드 P사(월 매출 2억 원 규모)도 마찬가지였다. GA4를 도입했지만 구매 전환 이벤트, 장바구니 담기, 결제 시작 이벤트가 부정확하게 집계되어 광고 채널별 실제 기여도를 파악하기 어려웠다. 잘못된 데이터로 광고 예산을 배분하다 보니, 실제로는 메타 광고가 구매 여정의 초기 단계에 큰 기여를 하고 있었지만 라스트클릭 기준에서는 전혀 보이지 않아 메타 광고 예산을 삭감하는 오류가 발생했다. 이 케이스에서는 GTM과 GA4를 활용해 이커머스 이벤트 추적 시스템을 처음부터 다시 구축한 과정과 그 결과를 구체적으로 소개한다. 6주간의 재구축 프로젝트가 이후 수개월의 마케팅 효율 개선으로 이어진 실제 경험이다.

문제 진단: 기존 추적 시스템의 한계

프로젝트 시작 전 P사의 GTM 컨테이너를 감사한 결과 세 가지 심각한 문제점이 발견됐다. 첫째, GA4 기본 구성 태그가 GTM과 하드코딩 방식으로 이중 설치되어 있어 페이지뷰가 실제보다 약 1.8배 과집계되고 있었다. 이로 인해 이탈률과 세션당 페이지 수 데이터가 모두 왜곡된 상태였다. 트래픽 분석 보고서의 기본 지표가 모두 실제와 달랐으니, 그 위에서 내린 모든 마케팅 판단이 흔들리는 기반 위에 세워진 것이었다. 둘째, '구매 완료' 이벤트 트리거가 주문 완료 페이지 URL('/order/complete')만 매칭하도록 설정되어 있었는데, 모바일에서 동일 페이지 URL이 '/m/order/complete'로 다르게 처리되어 모바일 구매의 상당 부분이 집계에서 누락되고 있었다. 실제로 전체 구매의 65%가 모바일에서 발생했는데, 집계된 전환 데이터의 모바일 비중은 28%에 불과했다. 데스크탑 중심으로 왜곡된 전환 데이터는 광고 타겟팅과 랜딩 페이지 최적화 방향 모두를 잘못 이끌고 있었다. 셋째, 장바구니 담기, 결제 시작 등 중간 단계 이벤트가 전혀 추적되지 않아 구매 퍼널의 어느 단계에서 이탈이 많은지 파악할 수 없었다. 마케팅팀은 최종 구매 전환만 보고 있었고, 그 이전 단계에서 얼마나 많은 잠재 고객이 이탈하는지 보이지 않았다. 이 세 가지 문제를 해결하기 위해 6주간의 GTM 및 GA4 재설정 프로젝트를 진행했다.

해결책 설계: dataLayer 기반 이커머스 추적 아키텍처

P사의 개발팀과 협업해 GA4 권장 이커머스 이벤트 스펙에 맞는 dataLayer 설계를 진행했다. GA4가 표준으로 정의한 이커머스 이벤트(viewitem, addtocart, begincheckout, purchase 등)를 기반으로 P사 비즈니스에 맞게 커스텀 파라미터를 추가했다. 특히 P사에서 중요하게 생각하는 '브랜드별 상품 카테고리', '회원/비회원 구분', '첫 구매/재구매 여부' 파라미터를 이벤트에 포함시켜 세그먼트별 분석이 가능하도록 설계했다. 개발팀이 서버 사이드에서 각 이벤트 발생 시 dataLayer.push를 삽입하는 방식으로 구현했다. 이 방식은 클라이언트 사이드 JS 오류나 광고 차단기에 영향받지 않아 데이터 신뢰도가 높다. CSS 선택자나 URL 패턴에 의존하는 트리거 방식은 사이트 구조가 조금만 바뀌어도 데이터가 누락되는 취약점이 있지만, dataLayer 방식은 서버 로직과 연결되어 있어 안정적이다. purchase 이벤트의 경우 트랜잭션 ID, 결제 금액, 할인 금액, 세금, 배송비, 쿠폰 코드, 상품 목록(상품 ID, 이름, 카테고리, 수량, 단가)을 모두 포함하도록 설계했다. 이 데이터가 GA4에 정확히 수집되면 상품별 매출 기여도, 카테고리별 수익성, 할인/쿠폰 효과 분석까지 가능해진다. 모바일과 데스크탑 모두에서 동일한 dataLayer가 push되도록 하여 기기별 추적 누락 문제를 근본적으로 해결했다.

GTM 설정 구현: 태그와 트리거 최적화

dataLayer 설계가 완료된 후 GTM에서 실제 태그와 트리거를 구현했다. 먼저 기존 하드코딩 GA4 코드를 완전히 제거하고, GTM을 통해서만 GA4를 로드하도록 일원화했다. 이 작업만으로 페이지뷰 이중 집계 문제가 해결됐다. GTM의 GA4 이벤트 태그를 각 이커머스 이벤트에 대응하도록 설정했다. 트리거는 모두 커스텀 이벤트 트리거로 설정해 dataLayer에서 특정 이벤트명이 push될 때만 각 태그가 실행되도록 했다. CSS 선택자나 URL 패턴 의존 트리거는 완전히 제거했다. addtocart 이벤트 트리거는 dataLayer에서 'addtocart' 이벤트가 발생할 때 실행되도록 설정했으며, 파라미터로 items 배열(상품 ID, 이름, 가격, 수량), value, currency를 전달하도록 구성했다. GTM 미리보기 모드와 GA4 DebugView를 병행 활용해 각 이벤트가 올바르게 실행되고 데이터가 GA4에 정확히 전달되는지 검증했다. 특히 모바일과 데스크탑 모두에서 체크아웃 플로우 전 과정을 시뮬레이션하며 이벤트 누락이 없는지 확인했다. 이 검증 과정에서 모바일에서 결제 시작(begincheckout) 이벤트가 일부 기기에서 발동하지 않는 추가 버그를 발견해 수정했다. 구글 광고 전환 태그도 GTM을 통해 재설정했으며, GA4 전환 가져오기 방식으로 구글 광고와 GA4의 전환 데이터를 일치시켰다.

성과: 데이터 정확도 개선과 인사이트 발견

GTM 재구축 완료 후 4주가 지나 데이터를 비교 분석한 결과 상당한 변화가 발견됐다. 모바일 전환 추적이 정상화되면서 집계된 전환의 모바일 비중이 28%에서 64%로 증가했다. 이전 데이터가 얼마나 왜곡되어 있었는지 명확히 확인된 것이다. 모바일 전환 데이터의 복구는 단순한 수치 수정이 아니라, 모바일 UX 개선 우선순위와 모바일 광고 예산 배분 결정을 전면 재검토하는 계기가 됐다. 구매 퍼널 분석도 처음으로 가능해졌다. 장바구니 담기 → 결제 시작 → 구매 완료의 각 단계별 이탈률을 분석한 결과, '결제 시작 → 구매 완료' 단계에서의 이탈률이 68%에 달한다는 사실이 발견됐다. 이 단계에서 이탈하는 사용자의 70%가 모바일 사용자였으며, 모바일 결제 UX 개선이 시급한 것으로 파악됐다. 이 인사이트는 추적 시스템 재구축 이전에는 전혀 알 수 없었던 정보다. 광고 채널별 어트리뷰션도 새롭게 파악됐다. DDA(데이터 기반 어트리뷰션) 모델로 분석하자 메타 광고가 구매 경로 초기 단계에서 38%의 기여를 하고 있음이 밝혀졌다. 이전에 삭감됐던 메타 광고 예산을 복원하고 전략을 재조정했다. 라스트클릭 기준으로 보이지 않던 기여도가 멀티터치 어트리뷰션 분석에서 드러난 것이다. 정확한 추적 데이터가 없었다면 이 의사결정을 내릴 수 없었을 것이다.

비즈니스 개선: 데이터 인사이트의 실제 적용

정확한 데이터를 확보한 후 P사가 실행한 개선 작업과 그 결과를 정리한다. 데이터 인사이트가 실제 비즈니스 행동으로 이어지는 과정이 이 프로젝트의 핵심 성과다. 모바일 결제 UX 개선을 먼저 실행했다. 모바일 결제 페이지에서 카드 정보 입력 필드 수를 줄이고, 카카오페이·네이버페이·토스 간편결제를 상단에 노출하도록 개편했다. 이 변경 후 모바일 결제 전환율이 4.2%에서 6.8%로 약 62% 향상됐다. 단일 UX 개선으로 이 수준의 전환율 향상을 이끌어낸 것은 데이터가 명확히 문제 지점을 지목했기 때문에 가능했다. 광고 예산 재배분도 실행했다. 메타 광고 예산을 복원하고 '인지 캠페인'과 '리타겟팅 캠페인'을 구분해 운영했다. 메타 광고 예산 복원 후 전체 광고 ROAS가 320%에서 410%로 개선됐다. 멀티터치 어트리뷰션 분석이 광고 예산 배분의 근거가 된 것이다. 장바구니 이탈 리타겟팅도 새롭게 시작했다. 장바구니 담기 이후 7일 내 미구매 사용자를 GA4 오디언스로 설정해 구글 광고와 카카오 광고에서 리타겟팅 캠페인을 운영했다. 이 오디언스는 이전에는 장바구니 이벤트가 추적되지 않아 만들 수 없었던 세그먼트다. 장바구니 이탈 리타겟팅 캠페인의 ROAS는 일반 캠페인 대비 2.3배 높았다.

프로젝트에서 얻은 GTM·GA4 운영 원칙

이 프로젝트를 통해 도출한 GTM·GA4 운영의 핵심 원칙을 정리한다. 이 원칙들은 P사의 사례에서 직접 검증된 것들이다. 첫째 원칙은 dataLayer를 서버 사이드에서 삽입하라는 것이다. 클라이언트 사이드 JS로만 구현하면 페이지 로드 순서나 JS 오류로 인해 이벤트가 누락될 수 있다. 핵심 전환 이벤트는 서버에서 직접 dataLayer를 삽입하는 방식이 훨씬 안정적이다. 둘째 원칙은 태그 추가 전에 감사 먼저 하라는 것이다. 새로운 태그를 추가하기 전에 기존 컨테이너 상태를 감사해 중복과 오류를 제거해야 한다. 추가만 반복하다 보면 컨테이너가 복잡해지고 관리가 어려워진다. P사의 경우 감사만으로도 이중 집계 문제를 해결했다. 셋째 원칙은 모바일과 데스크탑을 항상 분리 테스트하라는 것이다. 이커머스 전환 경로는 기기별로 다르게 작동하는 경우가 많다. 반드시 두 환경에서 모두 QA를 수행해야 한다. P사의 가장 큰 추적 오류도 모바일 URL 패턴이 데스크탑과 달랐기 때문에 발생했다. 넷째 원칙은 데이터 차이가 나도 당황하지 말고 원인을 찾으라는 것이다. GA4와 광고 플랫폼의 수치 차이는 어트리뷰션 모델, 집계 방식 차이로 발생한다. 차이의 원인을 파악하면 어트리뷰션에 대한 더 깊은 이해를 얻을 수 있고, 어느 데이터를 어떤 의사결정에 활용해야 할지 명확해진다.

마무리

P사의 GTM·GA4 재구축 프로젝트는 단순한 기술적 작업이 아니라 비즈니스 의사결정의 근거를 바로잡는 과정이었다. 모바일 전환 누락이라는 한 가지 오류가 광고 예산 배분 전략 전체를 잘못된 방향으로 이끌고 있었다. 정확한 데이터 수집 체계를 구축하는 데 투자한 6주가 이후 수개월간의 마케팅 효율 개선으로 이어진 것이다. 이커머스를 운영한다면 광고비를 늘리기 전에 추적 시스템을 검증하는 것이 먼저다. 데이터 인프라가 흔들리면 그 위에서 내리는 모든 판단이 흔들린다.

자주 묻는 질문

GA4 이커머스 이벤트 추적을 위해 개발자가 반드시 필요한가요?

핵심 전환 이벤트(purchase, begincheckout 등)의 정확한 추적을 위해서는 dataLayer 삽입 코드를 개발팀이 구현해야 합니다. 단, 단순한 클릭 이벤트, 스크롤 추적, 페이지뷰 등은 GTM의 자동 이벤트 수집과 기본 트리거로 개발자 없이 설정 가능합니다. 이커머스 전환 추적만큼은 개발팀 협력을 강력히 권장합니다.

GA4 DebugView는 어떻게 사용하나요?

Chrome 확장 프로그램 'Google Analytics Debugger'를 설치하고 활성화한 후 사이트를 방문하면, GA4 관리 화면의 '구성 DebugView'에서 실시간으로 발생하는 이벤트를 확인할 수 있습니다. GTM 미리보기와 함께 사용하면 태그 실행부터 GA4 데이터 수신까지 전 과정을 검증할 수 있어, 설정 오류를 배포 전에 발견할 수 있습니다.

이커머스 전환 데이터의 GA4와 광고 플랫폼 수치 차이가 클 때 어느 것을 기준으로 해야 하나요?

전략적 의사결정의 기준은 GA4를 사용하는 것을 권장합니다. GA4는 모든 채널을 통합해서 보기 때문에 편향이 적습니다. 다만 각 광고 플랫폼의 최적화 알고리즘은 해당 플랫폼의 전환 데이터를 기반으로 작동하므로, 최적화 목적으로는 해당 플랫폼 데이터를 사용합니다. GA4 전환을 구글 광고로 가져오는 방식을 사용하면 두 데이터의 불일치를 줄일 수 있습니다.

장바구니 이탈 리타겟팅 오디언스를 GA4에서 어떻게 만드나요?

GA4 관리 오디언스 메뉴에서 '새 오디언스 만들기'를 선택합니다. 조건으로 'addtocart 이벤트를 발생시켰지만 purchase 이벤트는 발생시키지 않은 사용자'를 설정하고, 멤버십 기간을 7일로 설정합니다. 이 오디언스는 구글 광고에서 리타겟팅 캠페인의 타겟으로 사용할 수 있으며, 장바구니 이벤트가 정확히 추적되어야 만들 수 있습니다.

GTM 컨테이너가 너무 복잡해져 관리가 어렵습니다. 정리하는 방법이 있나요?

사용하지 않는 태그, 트리거, 변수를 비활성화하거나 삭제하는 정리 작업이 필요합니다. GTM 태그 감사 스프레드시트를 만들어 각 태그의 목적, 담당자, 마지막 수정 날짜를 기록하고, 6개월 이상 사용하지 않은 태그는 삭제를 검토하세요. 분기별로 컨테이너 상태를 점검하는 일정을 캘린더에 등록해두는 것을 권장합니다.

사이트 검토 정보

크레피카는 크리에이터와 마케터를 위한 무료 유틸리티 사이트입니다. 실무 도구, 편집 가이드, 문의 정보, 개인정보처리방침, 이용약관, RSS, robots.txt, ads.txt, 사이트맵을 제공해 사용자와 검색엔진이 자바스크립트 렌더링에만 의존하지 않고 사이트 구조를 이해할 수 있게 합니다.

광고는 Google AdSense 자동 광고로 노출될 수 있습니다. 이 정적 크롤러 페이지에는 수동 광고 슬롯을 삽입하지 않으며, 광고는 도구 결과나 편집 추천 내용에 영향을 주지 않습니다.
